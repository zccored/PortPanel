# 04 · .wbt 图纸版本策略

状态：**FROZEN**（2026-10-23）
优先级：**最高**（唯一会造成用户数据永久丢失的项）

## 1. 现状问题

- `_deserialize_node`（flow_editor.py:12379）遇未知节点类型**静默 `return None`**（:12479）；
- `.wbt` 顶层 `version` **只写不读**；
- 结果：新节点进图纸 → 旧版打开丢节点 → 一保存**永久丢失**。

## 2. 新规则

| 场景 | 写入 | 读取 |
|---|---|---|
| 只用老节点 | `version: 1`（旧版可读） | 正常 |
| 含新节点类型 | `version: 2` + `required_node_types: [...]` | 正常 |
| 读到 version > 本程序支持 | 不写（只读模式） | **禁保存** + 明确提示"请升级 PortPanel" |
| 读到未知节点类型 | — | **打警告 + 建占位节点**，不再静默丢弃 |

## 3. 实现要点

1. `_serialize_flow` 落盘前计算 `required_node_types`（按 `type(node).__name__` 去重）；
2. `_deserialize_node` 的兜底 `return None` 改成：`warnings.append(...)` + 返回 `UnknownNodePlaceholder(原始 ndata)`；
3. 占位节点**必须能原样再序列化**（保住 ndata），保证"打开→保存"不丢数据；
4. 只读模式：`self._readonly = True` → 屏蔽保存/另存为，标题栏加 `[只读]`。

## 4. 验收

1. v1 图纸经新版打开保存 → 仍是 `version: 1`，字节级 diff 只有时间戳；
2. v2 图纸 → 旧版打开：不崩、有提示、**保存被禁止**；
3. 构造一个含未知类型节点的 v2 图纸，新版打开 → 有警告、占位可见、再保存 ndata 完整。

## 5. 风险

| 风险 | 处置 |
|---|---|
| 占位节点被用户误连线 | 占位节点不可连线、不可执行，工具栏显示告警计数 |
| 已发布旧版无法修补 | 只能靠版本号 + 文档 + 新版提示兜底，**文档里写明不向下兼容** |
